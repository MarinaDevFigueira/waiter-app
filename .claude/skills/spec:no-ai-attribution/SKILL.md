# Never add AI attribution or co-authorship

Never mention Claude Code, AI assistants, or add co-authorship attribution in commits, PRs, or code.

## Rule

**NEVER include any reference to AI tools in:**
- Git commit messages
- Git commit co-authors (`Co-Authored-By`)
- Pull request descriptions
- Code comments
- Documentation
- Any project files

The code and commits should appear as if developed manually by the team.

## Examples

### ❌ WRONG — AI attribution in commit

```bash
git commit -m "feat: add login form

Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>"
```

### ❌ WRONG — AI attribution in PR

```markdown
## Summary
Added new login component

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

### ❌ WRONG — AI attribution in code

```javascript
// Generated by Claude Code
export function calculateTotal(items) {
  return items.reduce((sum, item) => sum + item.price, 0);
}
```

### ✅ CORRECT — No attribution

```bash
# Commit
git commit -m "feat: add login form with validation"

# PR description
## Summary
Added new login component with form validation and error handling.

# Code
export function calculateTotal(items) {
  return items.reduce((sum, item) => sum + item.price, 0);
}
```

## Why

- **Professional presentation**: Code should appear as team-developed work
- **No tool advertising**: Project artifacts should not advertise development tools
- **Clean history**: Git history should focus on changes, not tooling
- **Team attribution**: Commits represent team work, not individual tools

## This applies to

- Commit messages
- Commit trailers (Co-Authored-By, Helped-by, etc.)
- Pull request titles and descriptions
- Code comments
- Documentation (README, CONTRIBUTING, etc.)
- Configuration files
- Any text visible in the repository

Keep all project artifacts free from AI tool mentions.
